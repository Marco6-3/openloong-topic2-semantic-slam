# 已验证的初赛架构

## 决策结论

初赛主链路固定为原生 ROS 2 Jazzy，不混装 ROS1：

```text
ROS1 data.bag
  │  rosbags 无损容器/序列化转换 + 话题计数门禁
  ▼
ROS2 MCAP ──► Livox 消息接口 ──► FAST-LIO2（固定提交）
                                  │
                     ┌────────────┴────────────┐
                     ▼                         ▼
              /Odometry                 配准逐帧点云
                     │                         │
高质量 RTK ──► ENU ──┴─► 鲁棒对齐/平滑校正 ──┼─► 按时间校正 + 体素融合 ─► ENU 几何地图
                     │                         │
                     ▼                         └─► 机体因果滑窗 ─► RandLA-Net 点概率
             官方格式 path.yaml                                      │
                     │               ENU 位姿投影 + 多帧概率融合 ◄─────┘
                     │                              │
                     │                              ▼
                     └────────────────────► 模型语义地图/动态候选
                                                    │
                                                    ▼
                                        PCD + YAML + 指标 + RViz
```

选择该路线的原因：原始 bag 是 ROS1，但当前可复现环境和后续仿真接口是 ROS 2；原版 FAST-LIO2 是 ROS1，直接混用会让构建和运行环境不可复现。项目改用固定在提交 `2fffc570a25d0df172720bac034fbdb6a13d2162` 的 ROS2 移植版，第三方源码由脚本获取且不提交进仓库。仓库内只实现与 bag 完全一致的 `livox_ros_driver2/CustomMsg` 接口，不引入采集硬件驱动和 Livox SDK。

## 分层与接口

1. 数据适配层：`convert_bag_ros2.py` 保留 LiDAR、IMU、RTK 话题，转换后逐话题核对消息数；`/rosout` 与算法无关，明确排除。
2. 里程计层：FAST-LIO2 只消费 `/livox/lidar` 和 `/livox/imu`，输出 `/Odometry`、`/cloud_registered` 和 `/cloud_registered_body`。配置集中在 `config/fast_lio_mid360.yaml`。
3. 全局层：RTK 先转换到固定 ENU；LIO/RTK 用时间戳关联和鲁棒 SE(2) 对齐，再用平滑 RTK 残差校正完整 LIO 轨迹。
4. 地图层：不能只修正轨迹。每帧 `/cloud_registered` 使用同一时刻的全局校正重新投影到 ENU，再做 20 cm 体素融合。跨帧观测次数可过滤瞬态点。
5. 语义层：正式接口为 `label:uint16 + confidence:float32 + rgb:uint32`。主链路使用 4.9 MiB、124 万参数的 RandLA-Net SemanticKITTI 权重；40 帧因果滑窗每 10 帧推理一次，点结果按同帧 LIO/RTK 位姿投影到 ENU 的 20 cm 体素并平均类别概率。低于 0.35 的结果为 `unknown`；高度启发式仅作故障兜底。
6. 交付层：独立校验 PCD 文件长度、字段、点数、有限值和坐标范围；独立校验官方 YAML 字段、总点数、经纬度和时间顺序。
7. 打包层：`package_submission.py` 再次执行校验、记录每个文件 SHA-256、检查 500 MiB 上限并生成官方邮件主题；脚本不会擅自发送邮件。

## 已通过的可行性与全量门禁

2026-08-29 使用真实 60 秒样例完成：

- ROS1→ROS2 MCAP 转换后 14,400 条消息一致；
- Livox 接口和 FAST-LIO2 在 ROS 2 Jazzy、Eigen 5.0.1、PCL 1.15.1、GCC 14.4 下 Release 构建成功；
- 实时运行输出 597/600 个里程计和配准点云帧，少的 3 帧为初始化阶段；
- 3× 播放只输出 587 帧，因此否决；2× 播放恢复 597 帧，设为默认并增加最多缺 5 帧的完整性门禁；
- 样例地图 86,550 点全部有限；LIO/RTK 刚体对齐水平 RMSE 0.169 m，RTK 校正后 3D RMSE 0.027 m；
- 逐帧校正重建得到 177,156 个至少被两帧观测的 ENU 体素点；
- 当时 13 个自动化测试通过；加入语义模型后现为默认环境 14 通过/4 跳过、语义环境 18 个全部通过。

同日完成全量 652 秒候选运行：FAST-LIO 输出 6,518/6,522 帧，缺失 4 帧符合初始化门禁；2× 回放墙钟 333.020 秒、有效 1.958× 实时、峰值 RSS 518.164 MiB。LIO 仅刚体对齐 RTK 的水平 RMSE 为 3.271 m，平滑校正后 3D RMSE 为 0.089 m。逐帧重投影和 20 cm 体素融合得到 1,524,881 个至少跨两帧观测的有限点，过滤 1,270,006 个单帧瞬态体素。完整指标见 `results/final-run.md`。

语义全量运行读取 8,774,139 个点，完成 652 次 45,056 点模型推理，点云和轨迹最大时间误差为 0。最终 1,524,881 个地图点中 99.89% 获得模型空间覆盖，覆盖点平均融合 9.18 次观测；低置信或无覆盖点保留为 `unknown`。在 RTX 4090 上模型前向平均 14.26 ms、P95 28.43 ms，峰值显存 212.0 MiB；完整管线 318.42 秒，其中 CPU KNN/融合占主要时间。18 个测试在语义环境全部通过。

可视化 bag 按消息 Header 重定时，RViz 由 `/Odometry` 生成的动态 TF 跟随 `body`，录屏直接绑定 RViz X11 客户窗口。最终 WebM 为 113.161 秒、1453×846、30 fps，已通过媒体探测和等间隔抽帧检查。

## 尚不能凭空消除的边界

- bag 未提供经过官方确认的 LiDAR–IMU 物理外参。当前采用 ROS2 移植版的 MID360 初值并开启在线细化；最终参数必须结合完整地图复查。
- heading 没有 Header，且零方向、正方向未获官方确认，所以不作为强约束；全局航向由 LIO 轨迹与 RTK 位移共同估计。
- 组委会不提供固定语义类别，允许模型自行定义，但要求适合边缘设备。提交字段、评分方法及“边缘设备”的具体大小/时延上限仍未明确；最终报告必须自行披露标签来源、权重大小、参数量、运行硬件和时延。
- 视频录制仍需要 X11 图形会话；当前脚本使用 `xwininfo` 定位窗口，并以 VP8 WebM 输出。无图形会话的 CI 只能执行视频文件校验，不能重新录制。
